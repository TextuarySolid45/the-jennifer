## Problem Statement

The site works — auth, ordering, order-status flow are all live — but it visually reads as a side project, not a small storefront. It's about to be shown to more than immediate family (aunt's friends, husband's coworkers), which raises the bar on first impression. The header is dominated by an oversized circular family-portrait illustration with no visible site name anywhere, and the live menu is currently showing seed/test data (an item literally named "a" using the logo as its photo), which makes the whole page feel unfinished.

## What Makes This Cool

A same-palette redesign that keeps the hand-drawn family portrait as a small, warm brand mark instead of the hero of the page — giving the site an actual name/wordmark ("The Jennifer"), a hero section that surfaces the next scheduled visit (tying directly into the not-yet-built visits feature), and a real menu grid with sourdough/pretzel/bagel content instead of placeholder test rows. Nothing about the backend, auth, or data model changes — this is a layout/typography/content pass on top of what already exists.

## Constraints

- No real bread photography exists yet — the design needs a tasteful placeholder (icon-style) for menu item images until Jennifer sends real photos, not broken image icons or the logo reused as a stand-in.
- Must keep the existing green/gold palette (`src/util/theme.ts`) and MUI as the component library — this is a styling/layout pass, not a framework change.
- Audience is close family plus a modest extended circle (aunt's friends, husband's coworkers) — polish matters, but this doesn't need to hold up to public/viral scrutiny.
- Frontend-only scope for this doc. No auth, payment, or visits backend work included (those are separate open threads from CLAUDE.md, intentionally deferred).

## Premises

1. The "unprofessional" feel is a branding/layout/content gap (no wordmark, oversized portrait-as-logo, default-heavy MUI typography, placeholder test data) — not a structural rebuild. Fixing the visual layer gets most of the way there. — agreed.
2. Direction A (Warm Artisan Bakery: serif headline, small badge logo, cozy hero, rounded cards) is the target look over a cleaner minimal-e-commerce alternative. — agreed.
3. Real bread photos don't exist yet — the design needs a graceful placeholder for menu item images until photos are available. — agreed.

## Approaches Considered

### Approach A: Warm Artisan Bakery (chosen)
Summary: Serif headline type, small round badge logo (~44px, matching the current "Sign In" button height) replacing the oversized portrait, hero section surfacing the next visit date, soft rounded cards on the existing cream/olive palette.
Effort: M (human: a weekend / CC: ~1-2 hrs)
Risk: Low
Pros: Fits a handmade-bread hobby business better than a generic e-commerce look; keeps the warmth of the existing palette; reuses the existing family portrait as a badge instead of discarding it.
Cons: Hero's "next visit" callout depends on visit data that isn't modeled yet (can hardcode/omit until the visits feature ships).
Reuses: Existing `theme.ts` palette tokens, existing `header.png` asset (cropped into a badge-sized export — see Next Steps), existing Accordion-based Menu/Orders structure.

### Approach B: Clean Minimal E-commerce
Summary: Sans-serif type, top nav (Menu/Orders/Visits), bold black CTA hero, filter chips, tight-bordered product grid.
Effort: M (human: a weekend / CC: ~1-2 hrs)
Risk: Low
Pros: Sharper, more modern "shop" feel; filter chips would scale well if the menu grows past a handful of items.
Cons: Reads more like a startup product than a family member's bread hobby — rejected as tonally colder for this audience.
Reuses: Same underlying palette tokens, same component structure.

## Recommended Approach

Approach A (Warm Artisan Bakery), full pass: header/wordmark, hero with next-visit context, menu grid/cards, Orders/Past Orders accordion styling, and a typography scale pass in `theme.ts`. Chosen because it matches the actual nature of the product (a family member's handmade bread, not a generic shop) and because the user picked it directly over Approach B when shown both side by side.

## Open Questions

- Font pairing: placeholder pick is **Fraunces** (serif, headlines) paired with the existing **Inter** (body text) — both free on Google Fonts. Not a hard commitment; swap freely during implementation if it doesn't read well against the palette.
- Sign-in button/flow restyle: **in scope**, as part of the header restyle in Next Steps step 2 — it lives in the same header block as the wordmark/badge, so restyling one without the other would look disjointed.
- When will real bread photos be available? Until then, menu cards use a placeholder icon system (see Next Steps step 3) — remember to give placeholder icons real `alt` text (e.g. "Sourdough loaf placeholder") rather than empty/decorative alt.
- No mobile screenshot was reviewed this session — the redesign should be checked at mobile widths before considering it done, since the current live site's Menu/Orders sections are accordion-based specifically for mobile stacking. Menu grid target: 1 column on mobile, 2 on tablet, 3 on desktop (matching the existing MUI breakpoint conventions already used elsewhere in the app).

## Success Criteria

- The site displays an actual name/wordmark ("The Jennifer") — not just the family portrait.
- The header no longer visually dominates the page with an oversized circular image.
- The menu section shows real content (or realistic placeholders), not the "a" / "a" test item.
- Typography and spacing read as intentional, not MUI-default-heavy.
- Layout holds up cleanly on both desktop and mobile widths.
